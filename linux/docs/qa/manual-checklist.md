# Linux 人工联调清单（托盘 / 快捷键 / 字幕窗口 / 音频路由 / 安装与更新）

> 维护者：build-verify（按 `windows/docs/qa/manual-checklist.md` 改写为 Linux 版）。
> 用途：自动化（L1–L8）在无头环境无法覆盖的**真实桌面**行为，必须由人在真机执行。
> 状态口径：**通过 / 失败 / 跳过（原因）/ 未验证**。未执行的一律保持「未验证」。
> 执行前先跑自动化基线（`docs/testing.md` 的 L1–L8），确认自动化层全绿。

## 0.1 ⚠️ 前置条件：需要一台没有其它输入焦点的桌面（硬性）

以下条目必须在安静、无他人使用的桌面上执行：

| 条目 | 项目 |
| --- | --- |
| M-01~M-08 | 托盘图标、tooltip、右键菜单、勾选态、托盘退出 |
| M-09~M-14 | 五个全局快捷键、失焦/最小化仍生效、去抖、冲突、退出后注销 |
| M-15~M-22 | 字幕窗跨应用置顶、三态切换、拖拽缩放、刷新恢复 |
| M-32 | **三入口幽灵组合（阻塞级）** |

原因：全局快捷键是系统级输入，会投递到不可预测的焦点上下文并可能触发用户其它软件的同名快捷键；
置顶/弹窗会遮挡用户正在看的内容。**不得在活跃工作会话上顺手测试。**

## 1. 托盘（AppIndicator）

### M-01 托盘图标显示
- **步骤**：启动应用 → 查看系统托盘/顶栏（GNOME 需启用 AppIndicator 扩展）。
- **通过标准**：出现 1 个应用图标；tooltip 为 `同传翻译 · 未启动`（未启动时）；无重复图标。
- **实测结果**：`未验证`

### M-02 托盘 tooltip / 菜单首项随状态变化
- **步骤**：依次制造 5 种状态：未启动 → 连接中 → 正常翻译 → 拔麦克风（音频异常）→ 断网（网络异常）。
- **通过标准**：tooltip 与菜单首项一致，文案只能是 `未启动 / 正在连接 / 正常翻译 / 音频异常 / 网络异常`。
- **实测结果**：`未验证`

### M-03 主窗口隐藏时右键菜单可用（关键项）
- **步骤**：关闭主窗口（非托盘退出）→ 右键托盘图标 → 点 `显示主窗口`。
- **通过标准**：菜单能弹出；主窗口恢复且未最小化；**正在进行的翻译不中断**。
- **实测结果**：`未验证`

### M-04 托盘勾选项与真实状态一致
- **步骤**：观察 `静音发言 / 收听通道 / 发言通道 / 字幕悬浮窗` 四个 CheckMenuItem；用快捷键改变状态后**重开菜单**再看。
- **通过标准**：勾选态与真实状态一致（不是缓存旧值）；`静音发言` 勾选态 = `speakMuted`。

### M-05 托盘菜单「设置」
- **步骤**：点击 `设置`。
- **通过标准**：主窗口显示并聚焦，设置对话框自动打开。
- **实测结果**：`未验证`

### M-06 托盘「开始同传 / 停止同传」文案切换
- **步骤**：无 session 时看菜单 → 开始同传 → 再看菜单。
- **通过标准**：无 session 显示 `开始同传`；有 session 显示 `停止同传`。
- **实测结果**：`未验证`

### M-07 托盘退出：sidecar 必须结束（关键项）
- **步骤**：1) `pgrep -af translator-bridge` 记 PID；2) 托盘菜单 `退出应用`；3) 5 秒后再查。
- **通过标准**：窗口/托盘图标全部消失；`translator-bridge` 进程 **0 个残留**；再次启动正常
  （无单实例锁残留）；`pactl list short modules | grep translator_` 为空（虚拟麦克风已卸载）。
- **实测结果**：`未验证`

### M-08 关闭主窗口进程仍在
- **步骤**：关闭主窗口 → `pgrep -af simultaneous-translator` → 等 10 秒再查。
- **通过标准**：应用进程与 sidecar 进程都仍在（关闭主窗口 = 隐藏到托盘，不是退出）。
  **无 AppIndicator 宿主时**：按契约 D7 降级为「关闭窗口即退出」（记录该环境下的实际行为）。
- **实测结果**：`未验证`

### M-28 启动中立即停止

- **通过标准**：不卡死、无僵尸连接状态；最终回「未启动」或明确错误；再次开始正常。
- **实测结果**：`未验证`

### M-29 设置未完成时按开始
- **步骤**：清空 API Key 后点开始。
- **通过标准**：提示「请先完成配置」一类可读文案；不启动 sidecar session；不崩溃。
- **实测结果**：`未验证`

### M-30 运行时开关不写回设置（关键项）
- **步骤**：1) 记录 `settings.json`（路径见 M-K01）内容与 mtime；2) 快捷键关收听+静音+取消静音来回 5 次；3) 再读文件。
- **通过标准**：`settings.json` 逐字节不变（或至少 `audio.listen/speak.enabled` 未被改写）；重启后配置仍一致。
- **实测结果**：`未验证`

### M-31 退出时正在翻译
- **步骤**：翻译进行中托盘「退出应用」。
- **通过标准**：进程干净退出；sidecar 0 残留；下次启动能正常开始新 session。
- **实测结果**：`未验证`

### M-32 【阻塞级】三入口幽灵组合证伪（契约 R §1.5.1）
- **前置**：发言通道已启用并已开始同传（`speak_enabled=true`）。
- **步骤**：`Ctrl+Shift+S` 把发言通道运行时关闭；依次尝试三个入口并在每步后看托盘勾选态：
  ① 主界面「静音」按钮（应禁用）；② 托盘「静音发言」（应 Err 且不勾选）；③ `Ctrl+Shift+M`（应提示「发言通道未启用，无法静音。」）。
- **通过标准**：三个入口都不让 sidecar 收到 `set_speak_muted`（无 `runtime.mute` 事件）；
  都有可读中文提示；托盘始终不出现「发言通道未勾选 + 静音发言已勾选」。
- **失败判据**：任一入口把 `speakMuted=true` 而 `speakEnabled=false` ⇒ **阻塞缺陷**。
- **实测结果**：`未验证`

## 6. Linux 音频路由专项（`docs/linux-audio-routing.md`）

### M-L01 隔离采集：模块生命周期
- **步骤**：同传（收听通道=系统声音）开始/停止各一次，期间与之后执行
  `pactl list short modules | grep translator_`、`pactl get-default-sink`。
- **通过标准**：运行中存在 `translator_mix` null-sink 与 loopback，默认 sink 临时切到 `translator_mix`；
  停止后模块全部消失、默认 sink 恢复原设备。
- **实测结果**：`未验证`

### M-L02 隔离采集：本软件译文不被回采（关键项）
- **步骤**：1) 用另一个应用播放人声/音乐（系统声音）；2) 开始同传（收听=系统声音，发言=麦克风）；
  3) 对着麦克风说一句可辨识的话；4) 观察字幕与译文。
- **通过标准**：系统声音能被翻译成字幕；**本软件播放的译文语音不会被再次送进识别**（无自激/重复翻译）；
  `pactl list short sink-inputs` 中本软件译文播放流绑定的 sink 是用户播放设备（不是 `translator_mix`）。
- **实测结果**：`未验证`

### M-L03 回环模式（指定播放设备）
- **步骤**：收听通道改为「指定播放设备回环」，选择当前默认 sink 的 monitor；开始同传并播放系统声音。
- **通过标准**：能采集该设备声音；允许采集到本软件输出（与 Windows 语义一致）；
  若选择的设备与译文播放设备相同，保存/启动时被拒绝并提示。
- **实测结果**：`未验证`

### M-L04 虚拟麦克风：创建/检测/会议软件可见
- **步骤**：设置 → 虚拟麦克风 → 创建/检测；打开会议软件（Zoom/Teams/Discord/浏览器）的麦克风列表。
- **通过标准**：`pactl list short sources` 出现 `translator_mic_source`；会议软件列表出现
  “Translator Virtual Microphone”；发言通道译文能被会议软件采集（可用会议软件「测试麦克风」验证）。
- **实测结果**：`未验证`

### M-L05 虚拟麦克风：生命周期
- **步骤**：停止同传 → 检查模块仍在；退出应用 → 再检查。
- **通过标准**：停止同传不卸载；退出应用后 `translator_mic`/`translator_mic_source` 消失；
  再次启动应用/创建时幂等（不重复加载、不误卸正在使用的模块）。
- **实测结果**：`未验证`

### M-L06 崩溃残留清理
- **步骤**：同传中 `kill -9 <主程序 PID>` → 检查 `pactl list short modules` 与默认 sink →
  重新启动应用 → 观察日志/模块。
- **通过标准**：主程序被杀后可能残留模块；重新启动后应用清理 `translator_*` 模块并恢复默认 sink；
  不残留状态文件（`$XDG_STATE_HOME/simultaneous-translator/audio-session.json` 已删）。
