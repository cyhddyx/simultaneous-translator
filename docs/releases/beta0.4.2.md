# 同传翻译 beta0.4.2

Windows x64 Beta 预发布版，应用版本为 0.4.2。本版新增“音频设备测试向导”，可以在开始同传前就地确认播放设备、麦克风和回环链路是否可用。向导依赖真实音频硬件，不同会议软件及设备组合尚未完成全面人工验收，因此继续作为预发布版提供。

## 更新内容

- “设置 → 音频”新增设备测试向导，提供三个互斥的测试：
  - **播放测试音**：向选定的播放设备播放约 1 秒 440 Hz 测试音，播放过程无错误即为成功。
  - **麦克风测试**：用选定的麦克风以 16 kHz 单声道录制约 3 秒，只在内存中计算峰值与均方根，达到阈值才标记“检测到信号”，否则提示“未检测到明显声音”。
  - **回环测试**：对选定播放设备对应的 WASAPI loopback 边播测试音边录约 1 秒，检测到超过阈值的信号才算成功。
- 设备列表复用“设置 → 音频”已有的枚举结果，默认选中系统默认设备；回环输入由选定扬声器自动映射，不需要单独选择。
- 同一时刻只允许运行一个测试：测试期间锁定设备选择器和其他测试入口，完成后可以重试或返回选择其他测试。关闭向导会作废当前请求，过期结果不会覆盖下一次测试。
- 正在进行同传时，“开始测试”不可用并提示先停止同传，避免临时探测进程与实时引擎争用音频设备。
- “未检测到信号”与设备打开失败等底层错误分开呈现：前者是测试完成但未通过，后者显示底层错误并提示关闭占用设备后重试。
- 测试全程在本机完成：不调用翻译模型、不需要 API Key、不保存录音，也不修改已保存的音频设置或 Windows 默认设备。
- 探测走独立的本地音频协议（Tauri 命令 → 一次性 Python sidecar），不经过 WebView 的 Web Audio API，也不启动完整同传会话；每次测试启动的临时 sidecar 在请求结束后关闭，不复用实时翻译 sidecar，并与设备枚举共用同一把音频锁串行化。
- 设置 schema 保持第 9 版：本版没有新增或改动设置项，升级不需要配置迁移。

## 安装与升级

下载 `simultaneous-translator_0.4.2_x64-setup.exe` 安装。升级前请停止同传并退出旧版应用；同页提供 `SHA256SUMS.txt` 供核对安装包。

- 从 0.4.1 或更早版本升级会保留原有设置、语言、设备选择与已保存的字幕记录，无需重新配置。
- 安装包未做代码签名，Windows SmartScreen 可能提示“未知发布者”。请先用同页 `SHA256SUMS.txt` 核对文件再运行。
- 其余环境要求不变：Windows 11 x64（进程级系统声音采集要求 Windows build 20348 及以上）、WebView2 运行时。

## 验证范围

已通过前端生产构建（tsc + vite）、Python 引擎与通道契约测试 150 项（86 + 18 + 36 + 10）、真实 sidecar 进程集成测试 96 项（PASS 96 / FAIL 0 / BLOCKED 0）、Rust 后端测试 53 项（另 1 项按设计跳过）、前端用例 45 项（音频路由 5、设备测试 5、语言能力 4、运行时状态 22、字幕窗口 9）。

`docs/superpowers/specs/2026-10-08-audio-device-test-wizard-design.md` 记录了向导的组件边界、探测协议、并发与生命周期约束及错误文案口径；`docs/qa/` 收录了本轮的验证矩阵与已知问题记录。

**尚未人工验收**：向导在真实扬声器、麦克风和回环端点上的实际表现，包括静音麦克风应显示“未检测到信号”、拔出设备应显示错误、以及正在同传时开始按钮被禁用这三条路径，仍需在 Windows 上用真实硬件执行。托盘菜单、全局快捷键与悬浮窗置顶等交互的验收状态沿用 beta0.4.1 的说明，本版未有变化。
